# 从教学流程到真实实现，逐步怎么验收

[返回第二版](../index.html) · [示例任务书](example-tasks.md) · [第一版验收](../../docs/acceptance.md)

这里补充第二版四个例子的门禁，不改动第一版契约，也不提供操作私有部署的执行命令。每一阶段都由当前环境的实际证据证明；本页合成状态、AI 的完成回复和截图不能充当真实实现证明。

## 1. 先搭接收与回执

- 选择 Tmux 作为优先入口，再加 Windows；Android Remote 可选。先用自己的 mock 验证，不急着接真实模型。
- 每个请求绑定操作者、项目、权限范围与原 ID，持久保存后才显示已接收。
- 区分接收、执行、构建、测试、验收、授权、发布和实际使用结果，不把一阶段写成下一阶段已完成。
- 断线后只读原 ID。写请求失去确认、404 或状态未知，不自动再投递；授权后人工核对是否产生副作用。
- 真实接口按[第一版契约](../../docs/contracts.md)与当前源码实现，不把页面里的 `demo-*` 字符串当成生产 ID。

**通过条件：** 用合成请求证明一次请求只对应一次受控执行；失去写确认后仅查原回执，不能重放开发、发布或安装动作。

## 2. 限制开发与构建权限

- 开发任务只看到授权项目。独立分支便于审阅与合并，文件与进程权限另行隔离。
- 开发、测试、签名、正式发布尽量分开账户或阶段。模型不能任意选择部署地址或读取发布凭据。
- 同步保留候选代码版本、任务回执和产物标识，合并后重新验收组合结果。
- APK 编译在 Linux 工具链完成。Android 模拟器用于安装、运行、测试；实际先核验虚拟化加速与资源，不承诺另一层虚拟机内的加速模拟器普遍可行。
- Android 测试环境可选择适合的独立宿主机或真机，按目标系统与设备能力决定支持范围。

**通过条件：** 合成任务能访问自己的测试项目，不能访问未授权项目；构建/测试流程对应同一候选，所需环境条件得到实际验证。

官方依据：[Android 命令行构建](https://developer.android.com/build/building-cmdline)、[模拟器命令行](https://developer.android.com/studio/run/emulator-commandline)、[硬件加速限制](https://developer.android.com/studio/run/emulator-acceleration)。

## 3. 新 APP 和更新分别测试

| 测试项 | 新 APP | 示例 0.1.0 → 0.1.1 |
|---|---|---|
| 基础运行 | 安装、启动、按钮、重启、支持设备 | 新功能及原有功能回归 |
| 数据 | 本地记录正确，跨日期符合设计 | 先装旧版、生成合成数据，再覆盖升级验证迁移 |
| 产物 | 真实版本、大小、摘要、支持范围 | 同应用 ID、满足更新要求的签名关系、递增版本编码 |
| 下载失败 | 说明失败，不安装半个文件 | 取消/部分文件/摘要不符不影响旧版可用状态 |
| 系统安装 | 安装来源授权与用户确认按系统处理 | 拒绝确认不显示更新成功；核实新版本实际安装与启动 |
| 恢复 | 保留候选和回执 | 程序产物回滚、数据备份恢复分别验证 |

APP 内点“更新”可以发起下载、校验和系统安装流程，用户不用手动找链接。**实际仍下载 APK，通常须系统确认。** 应用签名、可信元数据和文件摘要承担不同作用，不能互相替代。

安装器返回需要操作时明确引导；取消或未知结果不能标记成功。真实客户端还要按 Android 版本、安装来源和设备策略处理权限，不承诺所有平台免确认或静默安装。

**通过条件：** 新 APP 的基础行为有真实证据；更新以实际旧版路径验证数据迁移及失败保留旧版。包名一致不能证明数据一定不丢，回退 APP 版本也不保证旧版能读取已迁移数据。

官方依据：[应用更新要求](https://developer.android.com/google/play/app-updates)、[PackageInstaller](https://developer.android.com/reference/android/content/pm/PackageInstaller.html)。

## 4. 发布要有独立授权

- 用户验收与发布授权绑定指定候选，测试通过本身不发放发布权限。
- 最终候选在受控签名步骤完成后再测试、验收和授权；这三个阶段与发布必须指向同一份字节及哈希。重新签名或其他步骤改变文件，则重新走测试与授权，不能沿用旧文件的通过结论。
- 发布阶段复核应用身份、版本、大小、摘要、签名关系与元数据；下载路由受控并鉴权。
- 发布后从最终存储位置完整回读文件，确认实际提供的是同一个候选；回执记录最终结果。
- 失败、确认丢失或未知时保留证据，不覆盖记录、不自动重复发布。
- 不将 APK、签名资料、原测试记录或其他私有部署文件加入本公开教学仓库。

**通过条件：** 没授权不能发布，授权范围不能换候选。公开/私有可见范围按实际部署决定，最终产物能够核对。

## 5. 网页先预览，再部署

- 独立分支生成受控预览。未公开内容不能因预览可访问就被意外公开。
- 手机/桌面布局、链接、筛选、资源、控制台和意外外部请求逐项检查。
- 公开资料做文本、图片和元数据审查；AI 建议只供参考，仍人工检查关键内容。
- 经授权部署指定候选后，核对正式地址、HTTPS、资源与版本，保留上一版和回滚记录。
- 如果有后端、登录、上传或数据库，另行实现撤销、逐请求授权、输入限制与一致性备份；静态教学网页通过不证明服务端安全。

**通过条件：** 预览和正式地址分开；正式文件与验收候选一致；旧版本可回滚，数据恢复单独验证。

## 6. 回测与图表需要单独验证

第四例只说明“手机请求 → 受控数据 → 隔离回测 → 验收授权 → 图表网页 → 手机查看”这条链路，没有真实标的、参数推荐或收益结论，也不执行实际数据取数、策略计算或部署。

真实实现至少补齐这些要求：

- 只读数据与无交易权限，明确项目、接口引用、数据许可、保存和可发布范围。凭据通过安全配置引用，不进聊天、页面或日志。
- 取数有受控范围和资源限制，检查时间、缺失、重复与口径，错误或未知不能冒充完整数据。
- 每次运行绑定数据快照、脚本和配置版本，在隔离 Linux 环境执行；限制运行时间与资源。
- 费用、滑点、时间切分、信号与成交时序、未来数据边界都有实际检查证据；小样本可复核，不能把画出曲线当成方法正确。
- 报告说明假设、限制和数据版本；隐私与数据发布授权另行核对，不能把只读权限变成公开权限。
- 用户验收并授权指定候选后才发布，最终网页核对、访问控制与恢复分别落实。计算或发布确认丢失只读原回执，不自动重放。
- 输入、结果和回执按实际用途保留，独立备份与恢复演练不能靠手机缓存代替。

**通过条件：** 上述边界用授权/未授权合成身份和受控数据逐项证明。真实输入、运行与报告可追溯，未授权不能发布；方法与异常测试有实际证据。第四例网页动画、预设状态和合成数字不构成这些证明。

公开页面只展示十二个固定无单位数字，不运行策略。交互图表倒退到第七步前恢复未生成显示，切换场景隐藏图表；合成 GIF 默认不播放，用户播放/停止只切本地 GIF/SVG，不发送业务请求。GIF 单独展示完整链路，不跟随步骤，也不表示真实收益。

## 7. 安全与备份按用途补齐

作者没有程序开发背景，这套系统由 AI 协助实现。公开的是框架与思路，部署者负责结合用途定义权限和风险；可以请专业人员审核，再让 AI 逐项落实。

- 身份核验、令牌过期/撤销、最小权限和默认拒绝，不能靠前端隐藏按钮实现。
- 人机验证只是一层辅助，不能代替登录和授权；防火墙减少暴露面，也不保证应用逻辑安全。
- 模型、脚本、容器和构建依赖分别按能力与权限适配；工具输出不能自行授予发布权。
- 数据集中服务器会集中存储风险。备份放在独立位置，使用加密与版本，准备与实际验证恢复。
- 手机缓存、Git 分支、容器和跨项目调用都不是完整备份。程序回滚和数据库恢复分开处理。

**通过条件：** 用授权与未授权合成身份验证访问边界；令牌撤销有效；存储故障的恢复办法已经演练，而不只是写进文档。

官方依据：[OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。备份细节见[第一版说明](../../docs/backup-recovery.md)。
