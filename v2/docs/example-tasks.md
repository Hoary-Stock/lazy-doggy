# 四个可以交给自己 AI 的小任务

[返回第二版](../index.html) · [实施与验收](implementation-checklist.md) · [第一版接口](../../docs/contracts.md)

这些是**扩展蓝图和合成教学任务**，没有真实 APK、发布站点或已经跑通的自动 worker。先让自己的 AI 阅读第一版的架构与接口，再按当前环境实现；不要把下面的版本、状态或示例产物当成真实验收记录。

## 先给 AI 的共同要求

> 先复述需求、目标项目和你需要的权限。只在明确授权的项目范围内工作，建立独立分支和受限工作环境；不要访问其他项目、真实账户、私人资料或运行数据。
>
> 任务先保存原请求和持久回执，再领取执行。收到不等于执行，构建成功不等于测试通过，测试通过不等于授权发布。
>
> 手机失联或写操作没有确认时，只用原请求 ID 做只读查询，不能自动重放开发、构建、发布或安装操作。回执为未知时先核对证据，不能猜“肯定没执行”。
>
> APK 在隔离 Linux 工具链编译，Android 测试环境负责安装和运行；先验证模拟器宿主机与加速条件，不假定虚拟 Linux 里嵌套 Android 加速可用，也可选择真机或合适的独立宿主机。
>
> 修改、候选产物、测试结果都给出可核对证据。只有我看过并明确授权，才发布指定候选版本；开发任务不能随意拿到发布签名和正式部署凭据。
>
> 凭据不进入源码、日志、聊天截图或网页。保留当前可用版本与独立备份；失败或未知时说明状态，不能伪造成功。

独立 Git 分支便于合并，但不能隔离进程或文件权限。执行隔离、受控发布和跨项目权限需要单独落实。

## 示例一：从手机许愿，到打卡 APP

### 可以这样说

> 我想要一个小打卡 APP：喝水、散步、读书，三个按钮，点一下记住，再点一下能取消。能看最近七天就行。先离线保存在手机，不做账户和云同步。布局在小屏上也要好点。
>
> 先给我需求摘要，在独立项目里开发，Linux 构建 APK，Android 测试环境跑完后给我看结果。未经我授权，不发布。发布后客户端下载得到；APP 内也要有检查更新入口。

### 任务顺序

1. 校验操作者与项目权限，保存原请求和回执；让手机能看到“已接收、尚未开始”。
2. 确认三个打卡项、七天记录、本地保存和取消操作。其他想法暂列后续，不偷偷扩展范围。
3. 建立独立分支及受限 Linux 开发环境，只挂载这一个项目；实现页面和存储。
4. 用 Linux 工具链构建候选 APK，在受控步骤完成签名，再记录最终文件的应用 ID、显示版本、版本编码、兼容设备范围、字节数与 SHA-256。
5. 在经过核验的 Android 测试环境安装候选，检查启动、三个按钮、取消、跨日期、重启后记录和小屏排版。
6. 修理失败项并重新提供新的候选及对应证据，不能沿用旧候选的测试结论。
7. 你查看结果并授权发布这一份已签名、已测试的最终候选。受控发布阶段核对签名、元数据与文件，发布后回读完整文件校验。测试、授权和发布必须指向同一份字节与哈希；不能授权后重新签名改出另一份文件，再沿用旧测试结论。
8. 客户端提供受控下载入口；安装按 Android 的系统要求完成，不能宣称普通 APP 自动静默安装。

### 要交付什么

需求与范围摘要、独立改动、候选 APK 元数据、测试证据、发布授权记录、最终回执及恢复办法。公开示例只保留合成资料；自己部署的 APK、签名和测试记录在受控位置保存，不放进本仓库。

### 到这里才算验收

- 三项打卡与取消正确，跨日期和重启不丢应保留的记录；小屏无溢出、按钮易点。
- 没有登录、真账户访问或意外外部请求；项目权限不能访问其他工作区。
- 候选和实际发布文件的版本、字节数、摘要一致，安装可正常启动。
- 没授权不能发布；发布失败或确认未知保持清晰状态，不自动重试。

## 示例二：学习卡加收藏，并在 APP 内更新

### 可以这样说

> 我的学习卡想加一个收藏按钮，再加“只看收藏”。示例旧版是 0.1.0，新版叫 0.1.1；旧卡片和学习进度必须通过实测确认能保留。
>
> 做好之后，我想在原 APP 里点“检查更新”和“更新”，不用自己找链接下载安装包。下载、校验在 APP 内完成，安装交给 Android 系统让我确认。先测旧版覆盖升级和失败路径，再让我决定是否发布。

### 任务顺序

1. 保存原请求和回执。明确只加收藏与筛选，不清空旧数据，不改其他应用。
2. 从受控旧版建立独立分支，设计收藏字段与迁移；备份测试数据和旧候选。
3. Linux 构建新候选，在受控步骤完成签名，再测试这份最终文件。**应用 ID 保持匹配、版本编码递增，签名关系满足实际 Android 更新要求**；显示的 `0.1.0 → 0.1.1` 只是教学值。
4. Android 测试环境先安装测试旧版，生成合成卡片和进度，再按真实更新路径升级新候选。
5. 验证收藏、筛选、旧数据迁移、重启和版本显示；再测取消下载、部分文件、摘要不匹配、拒绝安装及权限变化。
6. 你验收并授权受控发布，服务端发布已测试的同一份最终文件及对应更新元数据，完整回读校验。签名或其他变化改动产物字节，就必须重新测试和授权，不能挪用旧候选证据。
7. 原 APP 检查并显示新版本和改动；用户点更新后，下载绑定当前候选的 APK，核对大小、摘要、平台和版本。
8. 校验通过后请求 Android 系统安装，通常需要允许安装来源并确认。安装后真实检查版本和数据，不能把“弹出了安装器”写成“更新完成”。

### 更新元数据至少说明什么

| 项目 | 教学示意或要求 |
|---|---|
| 应用 | 合成的学习卡项目，不使用原客户端身份 |
| 版本 | 显示版本 0.1.1；实际版本编码必须按旧版递增 |
| 产物 | Android APK，设备/ABI 范围按真实构建公布 |
| 字节数 | 构建完成后计算的整数，不猜测 |
| SHA-256 | 真实文件生成的 64 个小写十六进制字符，本文不提供示例摘要值 |
| 下载路由 | 受控同源、需授权且绑定候选，不接受模型提供的任意 URL |
| 签名与身份 | 服务端与系统各自验证；不能只靠文件摘要代替 |
| 发布记录 | 候选、测试、操作者授权及最终文件回读结果 |

### 到这里才算验收

- 用户可以从 APP 内发起检查、下载和系统安装确认，无需手动找下载链接。**仍下载 APK，也不承诺静默安装。**
- 新版收藏可用；旧数据迁移与保留通过实际测试，不能凭“包名一样”保证。
- 摘要不符、下载未完成或身份变化时不进入安装；拒绝更新不会先卸载旧版。
- 更新确认丢失时查原状态；不能重复触发安装或伪造升级成功。
- 旧数据有可恢复备份。程序版本回退和数据库回退分别设计；旧版本未必能读迁移后的新数据。

这是“自己的小 APP 加功能”的扩展示例。第一版的反馈功能针对 Remote、Tmux、PC **客户端本身**的问题；它不能证明任意项目都已经接入自动修复发布 worker。

## 示例三：从手机安排自己的学习网页

### 可以这样说

> 我想要一个个人学习网页，浅色、手机能看。首页、笔记列表和标签筛选就够，先用合成笔记，不要搬我的私人文件。先生成受控预览，我满意并授权后才发布到正式域名。

### 任务顺序

1. 接收需求、核验项目权限，保存回执；断线只读原请求，不重复部署。
2. 建立受限工作区和独立分支，明确哪些材料可以公开；不自动读取其他项目、邮箱或私人网盘。
3. 开发页面与筛选，构建候选资源。先用独立受控预览，未授权不替换正式站点。
4. 测试手机与桌面布局、筛选、链接、资源加载、浏览器错误和不该出现的外部请求。若有后台、登录、上传，则额外测试鉴权、撤销与输入边界。
5. 逐项检查文本、图片和元数据，排除凭据、私人地址与真实对话。机器扫描后仍人工看图。
6. 你从手机验收并授权部署指定候选。发布账户和开发账户尽量分离，凭据不嵌入页面。
7. 部署后核对正式地址、HTTPS 与候选资源，确认当前版本确实是验收的那一份。
8. 保留上一版及回滚记录；有数据库的网页另外备份与演练恢复。手机访问通过才交付。

### 到这里才算验收

- 手机能看、筛选正确、链接和资源有效，无意外泄露或业务请求。
- 未授权不能发布；候选预览不会误替换正式版本；部署结果可回读核对。
- 有恢复办法，静态文件回滚与数据库恢复不混为一谈。

## 示例四：从手机安排回测，再看图表网页

### 可以这样说

> 我想试一个泛化的均线交叉思路，先做流程测试，不连接实盘交易。数据使用已经授权、配置好的受控数据接口引用 `data-source-demo`；凭据通过安全配置传入，不放在聊天、代码或报告里。
>
> 先确认数据和项目范围，受控取数、检查完整性，再在隔离脚本里回测。请核对费用、滑点、时间切分、信号与成交时序、未来数据边界，给我能复核的记录。结果先生成受控图表预览，我验收并授权后才发布，最后在手机看。

这只是泛化教学愿望，**没有真实标的、参数推荐或收益结论**。本页不请求接口、不运行回测脚本，也不部署图表网站；示意曲线取自固定合成数字，不能据此判断任何策略表现。

### 任务顺序

1. 手机提出思路和数据接口的配置引用，不上传 Key、私人账户或真实交易记录；说明这次只读数据、没有交易权限。
2. 服务端核验身份与请求范围，持久保存原回执。收到不等于取数、运行或完成；失联后只读原请求，不重放计算和发布。
3. 确认项目隔离、数据授权、保存范围和可发布内容。模型读取受控引用，实际凭据留在安全配置；数据可访问不代表可公开。
4. 按授权和接口限制取数，核对时间戳、排序、缺失、重复、字段和数据口径。保存受控快照标识，不把密钥和私有原始数据加入结果网页。
5. 在受限 Linux 环境运行回测脚本，绑定脚本版本、数据快照和配置；限定时间和资源，不访问其他项目或实盘接口。
6. 把费用、滑点、时间切分、信号与成交时序、避免未来数据列入验收。提供小样本复核和异常测试，不把“脚本结束”当成方法正确。
7. 整理候选图表和检查说明。真实实现的图表应关联数据与脚本版本；本公开演示只显示十二个预设无单位数字，明确合成，不由策略计算。
8. 你核对方法、假设、数据范围、隐私和待公开内容，验收后授权发布指定候选；AI 回复不代替授权。
9. 发布脱敏图表网页，核对正式文件与候选一致，按内容控制访问；保留回执、上一版与恢复办法。部署未知时不自动重复发布。
10. 手机查看图表、检查说明和原报告。想换思路另开明确的新请求，原输入、结果与回执仍保留，不覆盖成新结论。

### 要交付什么

| 内容 | 真实实现时的要求 |
|---|---|
| 原请求与权限 | 原 ID、项目、只读数据范围、配置引用，不含凭据 |
| 数据 | 受控快照标识、口径与完整性检查；授权范围内保存 |
| 运行 | 脚本/配置版本、资源与时间边界、成功/失败/未知状态 |
| 核验 | 费用、滑点、时间切分、时序与未来数据边界的实际检查证据 |
| 候选报告 | 假设、限制、可复核信息及脱敏内容，不用图表代替方法检查 |
| 发布 | 指定候选的用户授权、最终文件核对、访问范围与回滚记录 |

### 到这里才算验收

- 合成测试身份只能读取授权数据与项目，不能调用交易接口、其他工作区或泄露凭据。
- 取数错误、缺失或未知不能默默变成正常结果；输入、脚本、配置与输出可追溯。
- 检查费用、滑点、时间切分和未来数据的要求有实际证据；本页预设状态不算已经验证。
- 图表不公开私人账户、未获发布授权的原始数据、接口私址或 Key。候选预览与正式发布分开，没授权不能发布。
- 正式页面与授权候选一致，手机能访问受控结果；失败保留记录、独立备份与恢复办法。

### 这个公开示例具体做了什么

互动图表的十二个合成数字是页面常量，第七步才显示曲线，退到前面步骤就回到尚未生成状态。没有日期、标的、货币或收益率单位，也没有真实数据与回测计算。

另有[合成教学动图](../assets/backtest-flow.gif)和[静态同图](../assets/backtest-flow.svg)，只解释完整链路。页面默认静态，用户自主播放/停止；停止回到静态图，不假称暂停在原帧。动图与上方逐步演示独立，不调用 API、回测或部署。

## 不止这四个例子

可以继续按自己的用途接本地 AI 整理邮件、私有网盘、实时通知，或把过去的小项目、学到的技巧整理成受控文档和脚本。模型不限 GPT，DeepSeek、千问也能按实际工具能力适配。**这些方向并非本仓库已实现的扩展**，各自需要权限、成本、测试和备份设计。

数据放在同一台服务器便于调用，也会集中存储风险。跨项目参考始终需要授权，客户端缓存不等于完整副本。[备份与恢复](../../docs/backup-recovery.md)
