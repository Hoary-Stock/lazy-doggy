01 / 使用场景

不用一直守着电脑。

选择一个日常场景，看手机与服务器怎样配合。下面是操作流程示意，不会调用真实模型。

01

电脑离手，任务不用重新开。

打开已有窗口，看看结果；把遗漏的要求补上，或者让 Agent 先停在检查阶段。长任务仍在服务器端，网络恢复后按原会话继续读取。

查看客户端搭建说明 ↗
  1. 手机打开已有窗口筛选 Agent，读取状态
  2. 服务器继续原任务保留会话与请求编号
  3. 手机看结果、补要求确认下一步再执行
修的是客户端自身Remote/Tmux 自己出现 Bug 或想加功能：手机提要求 → 授权 Agent 改客户端 → 服务器测试、构建和发布 → 应用内升级。反馈保存与更新入口已验收；一键全自动修复 worker 尚未验收。

一台 Linux 服务器

常开，运行控制服务与 Agent。外部模型路线先不配 GPU；配置按实际 CLI 和窗口数扩容。

↗

一个自己的域名

DNS 指向服务器，HTTPS 自动续期；模型密钥保留在服务端，不下发到客户端。

◎

自己的模型服务

合法使用的 CLI、订阅或 API，逐种核对登录和能力。模型费用与租服务器分开。

轻量起点，不是容量保证4 GB 可作为单用户、外部模型路线的规划起点；多个重型 CLI 和较多窗口可能需要 8 GB 以上。自托管大模型还要另算 GPU、显存和电力。
两段独立的网络手机只连接自己的服务器，模型请求由服务器上的 Agent 发出；已接受任务可在手机断线时继续。手机仍需能连到服务器，服务器出口与上游服务资格也须可用。参考链路使用 Nginx 和可选 Tailscale，详见网络说明。
存储坏了，可能丢多个项目文件与必要会话集中在服务器。硬盘/存储故障、误删或过大的写权限，可能造成大量数据丢失；手机不是完整备份。准备独立、加密、带版本的副本，并定期恢复验证。[S1] 备份与恢复 →

Android 客户端可参考 Flutter；Windows 客户端可参考 Electron。构建和原生验收需要对应平台的测试环境。[T2][T3]

08 / 真实问题，留下可复用的做法

最容易踩的坑，
不在聊天框里。

01超时后再次发送，可能执行两遍

原因：界面没收到回执，不代表服务器没收到。

做法：保留请求编号，先查询原回执；未知结果不自动重放写入。

02服务重启把 Agent 窗口一起停了

原因：服务进程、tmux server 和业务窗口的生命周期混在一起。

做法：先隔离进程归属、围栏和排空，再重启控制服务；核对 PID 与代际。只改 KillMode 不等于已经安全。[T4]

03单元测试通过，手机原生选文件仍失败

原因：Android 同一包缓存路径存在平台别名；原生选择器行为不等于测试替身。

做法：只允许可信的同包缓存映射，检查真实文件身份；在原生设备验收图片、文件、取消和恢复。

04缓存清理把待发送附件当作垃圾

原因：只按文件年龄、终端结束或无当前页面引用判断。

做法：跟踪草稿、复用和活动租约，删除前重核身份；盘点不完整、内容变化、归属不明就保留。

05筛选标签铺了好几行，遮住主要内容

原因：多个提供方和计数使手机标签区不断换行。

做法：改成一行横向滚动；选中状态和计数保留，主要空间交给任务列表。

06上下文和累计 Token 被当作同一件事

原因：不同来源的统计被拼成一个看似精确的数。

做法：上下文占用、累计输入/输出、估算和账单分开；没有数据就标未知。
