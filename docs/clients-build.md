# 三个客户端的构建规范

本页说明原实例已实现并验收的模块，以及供另一个 AI 重建同类产品的实现要求。公开仓库提供说明和脱敏展示，不包含实际服务配置、安装包或私有源码。新实现的路由、DTO 和状态命名统一以 [v1 契约](contracts.md)为准；下面的产品与能力表解释设计来源，不保证与原客户端二进制兼容。

## 产品边界

| 客户端 | 技术与平台 | 主要对象 | 必须保留的行为 |
| --- | --- | --- | --- |
| Tmux Remote | Flutter，Android | 已存在的终端窗口、窗格与结构化记录 | 窗口筛选、终端控制、原输入回执、模型设置、附件 |
| Remote Agent | Flutter，Android | 服务端 Agent 会话与持久消息队列 | 创建与继续会话、排队与状态、会话设置、窗口检查、附件 |
| PC Remote | Electron，Windows x64 | 通过网关控制上述服务 | 四模型窗口、统计、附件、Agent 更新、应用自身更新 |

两款手机应用是不同产品：窗口控制需要记录原窗口身份与代次；会话产品需要保存会话 ID、消息状态和队列引用。共享 DTO、网络和附件组件，分别实现导航及生命周期。Windows 客户端当前面向 Windows；公开规范不宣称支持其他桌面平台。

## Flutter 分层

- `screens`：窗口列表、会话列表、聊天、设置、统计、附件缓存和维护入口。
- `widgets`：模型设置、原生上下文占用、累计 Token、上传进度、更新回执、反馈浮层。
- `models`：解析服务端 DTO；未知值保留为未知，拒绝把缺失统计当成零。
- `services`：认证 HTTP、WebSocket、持久草稿与 outbox、原请求回执、版本更新和附件暂存。

网络错误不清空已有草稿。窗口列表采用单行横向滚动标签 `All / Claude / Codex / DeepSeek / Qwen`，显示全局数量；搜索与筛选可以组合。较窄屏幕和大字体必须能拖动并看到完整标签。反馈浮层默认位置避开标签与聊天输入区域，保留用户自行拖动的位置。

## Electron 分层

| 层 | 责任 |
| --- | --- |
| 主进程 | 原生文件选择、私有快照、固定网关请求、上传回执、系统凭据存储、安装器启动 |
| preload | 封闭的 IPC 操作与 DTO；不暴露任意路径、任意 URL 或通用命令执行 |
| renderer | 导航、窗口、消息、统计、进度和明确确认；不接收密钥或本机原文件路径 |
| 网关 | 服务端认证及既有后端适配、固定路由、流式传输、已接受版本元数据 |

Windows 保存的登录数据使用系统加密存储。测试注入只在显式测试模式与独立测试目录生效；正式使用不得通过渲染层开启它。

## 可扩展的模型能力映射

`provider` 是内部适配器身份，模型名是能力目录数据。品牌名不能替代具体模型的能力验证。

| 模型家族 | 当前适配方式 | 思考与上下文 | 图像 / 文件 | 状态 |
| --- | --- | --- | --- | --- |
| GPT | Codex 适配器 | 使用原生模型目录返回的 effort；不套用其他模型的档位 | 图像按原生能力；支持普通文件引用 | 已集成 |
| Claude | Claude Code 适配器 | 使用原生支持的模型与思考选项 | 支持已登记图片与普通文件引用 | 已集成 |
| DeepSeek | Harness / ACP 适配器 | 以实时模型能力与确认结果为准 | 图片须验证 vision；普通文件独立传递 | 已集成 |
| Qwen | Qwen Code / ACP，独立计量 API | `none / low / medium / xhigh`；32 / 64 / 128 / 256 Ki Token | 当前视觉输入禁用；支持普通文件 | 已集成 |
| Kimi | 待实现的独立适配器 | 档位、上下文与统计接口待验证 | 文件、视觉、工具能力均待验证 | 计划项，未测试 |

新 v1 能力 DTO 使用 `id, enabled, capabilities`，其中包含 `reasoning_efforts, context_choices, images, files, agent_update, archive_stop`；模型目录、可用性、并行预算和更新范围由同一能力服务补充。原实例内部不同名称在适配层转换，不要求客户端同时认识多种字段。未安装、不可用和未验证应返回不同状态与理由；不能仅新增一个按钮就宣称完成新模型接入。

## 设置与统计必须分开

1. **请求设置**：用户选择的模型、effort 和上下文容量，放在 `configured` 中。
2. **原生观测**：Agent 确认的实际模型、effort、容量及当前占用；尚未观测则 `observed:null`。v1 占用读数使用 `used_tokens, capacity_tokens, observed_at`。
3. **窗口累计 Token**：按窗口运行标识合并实际请求账本，显示已知 / 未知请求数量；有未知请求时总量标未知，`known_tokens` 仅为已知下界。
4. **账号或服务端统计**：按 provider、模型与 UTC 日期聚合；订阅额度是另一种数据，不能由 Token 数猜测。

Qwen 默认及最大容量为 256 Ki Token，可缩短为 128 / 64 / 32 Ki。设置修改需通过空闲状态检查；请求已接受不等于原生设置已生效。恢复会话后重新应用保存的 effort，并确认实际值。Qwen 独立链路统计真实 Token，没有订阅额度；未知读数不写成零。Bridge 的 Qwen 并行上限保持 16，客户端显示容量而不越过服务端准入。

## 重建验收

先用模拟四模型实现列表、设置和统计，再接实际适配器。至少覆盖：窄屏与大字体、四模型筛选、未观测上下文、部分账本、空闲 / 忙碌 guard、原 UUID 失联恢复、附件及更新确认。手机需要系统选择器验收；Windows 需要源码、打包、安装后三阶段及真实安装器数据保留检查。详见 [AI 构建流程](ai-build-playbook.md)。
