# 更新与手机反馈

本文将原实例已验证的行为与后续重建流程分开。新系统统一实现 [v1 契约](contracts.md)中的发布、维护与反馈接口；原实例功能范围不表示任何上游 CLI 或旧客户端自动兼容新接口。

## 三类更新入口

| 类型 | 用户流程 | 边界 |
| --- | --- | --- |
| Android 应用 | 查看已接受版本，下载正式 APK，交给系统安装 | 服务端模型与窗口继续运行 |
| Windows 应用 | 手动检查，下载并核验，单独确认安装，启动 NSIS | 保留系统加密登录数据、设备身份和草稿 |
| 服务端 Agent | 读取状态，预览范围与 guard，明确确认，保存原请求回执 | 不与客户端应用升级混为一谈 |

应用更新服务只返回平台、版本、规范文件名、精确长度、SHA-256 和固定下载路径。拒绝任意 URL 与重定向，不向客户端传递发布账号凭据。发布者先放入完整已验证的版本资产，再切换最新版本元数据；旧版本保留。

Windows 在安装前重新确认授权、版本及本地文件。取消、下载失败或字节不符的缓存不能安装。启动安装器后应用退出；服务端任务不因此退出。现有 Windows 验收使用真实安装器验证过加密登录、设备和未发送草稿保留；当前安装包未签名，摘要核验不替代代码签名。

## Qwen Code 与 DeepSeek Harness

| Agent | 已实现入口 | 更新范围 |
| --- | --- | --- |
| Qwen Code | 三个客户端 | 更新已验证的未来容器映像指针；现有窗口和任务保留原容器 |
| DeepSeek Harness | Remote 与 PC 的中央 Agent 更新面板 | 预览绑定的运行时维护；涉及窗口归档与支持的恢复，采用手动继续策略 |
| Claude Code / Codex | 既有中央更新面板 | 按各自受控运行时维护能力处理 |

Qwen 只串行化竞争的映像更新，已有活动窗口不是必须关闭的条件。DeepSeek 等运行时维护需检查忙碌任务、队列、现有维护和窗口身份；不能为升级强制绕过 guard。模型恢复能力不同，缺失恢复能力需明确显示，不能伪造自动继续。

更新保存唯一 request_id 和预览身份，确认后提交一次。失联时只 GET 原请求 / job，展示 `unconfirmed` 并禁用重复操作。原回执绑定服务来源与当时认证身份；换了认证身份后的恢复不能宣称已验证，更不能重发更新。面板必须显示作用范围、阻止原因及原回执状态。

重建 v1 将只升级未来实例的范围统一命名为 `future_instances`。维护作业状态使用 `accepted / building / verifying / activating / finished / failed / unknown`；`unconfirmed` 表示客户端确认链路不完整，应结合 `receipt_confirmed` 展示，不能虚构作业终态。

## 客户端自身的 Bug 与功能反馈

反馈对象是 Remote、Tmux 和 PC 客户端自身，例如筛选栏显示异常、更新按钮故障或想新增某个界面功能，不是业务项目的缺陷库。

两款 Android 应用都有可拖动反馈入口。点击后捕获当前应用画面，用户预览截图、填写复现说明并确认提交，客户端发送明确的一份报告。服务端保存私有报告，而不是公开发布截图或把报告当作终端指令。截图失败应提示重试；回退到 Flutter 画面捕获时，某些原生视图可能未被包含。

当前接收规范包括：

- 已认证 multipart，固定 PNG 截图、客户端报告编号、文字和允许的元数据。
- 截图最多 900 KiB，像素上限 800 万；说明最多 2,000 字符，元数据最多 16 KiB。
- 校验图片结构、字段白名单、文字脱敏、速率和存储额度；原子保存后给出回执。
- 不记录请求正文、认证信息或任意原始环境；拒绝时返回有限错误原因。

这些是原实例的已验证接收边界。新实现可在 `POST /v1/feedback` 沿用它们，统一错误格式与报告 UUID；原实例的路由和内部字段不成为另一套 v1 规范。

自动文字脱敏不能保证截图中的信息安全。用户需在发送前检查截图；公开展示只能使用合成界面并人工检查。

## 手机内完成修复与升级的使用流程

目标是人在手机上提出要求、查看修复、确认升级，不必手动切到服务器敲构建和发布命令。计算、测试、编译与包分发仍由服务器端执行；手机没有在本地编译 Android/Windows 应用。

`手机报告本客户端 Bug / 提新功能 → 私有回执 → 用户授权远程 Agent 修客户端代码 → 独立分支与测试 → 服务器构建 / 原生验收 → 确认发布 → 客户端内检查并安装更新`

已经验收的是受限报告接收、保存和客户端更新入口。把反馈自动派给修复 Agent、构建与发布的全自动 worker 不是已验收功能；可通过已有远程 Agent 会话完成有授权的修改，或另建工作流并单独验收。收到报告不会隐式批准修改源码或发版。

评审设置最长时限、材料大小、并发和调用预算。报告内容是不可信输入，不能请求任意命令、扩大目录权限或停止现有任务。AI 可以给出证据与补丁，不能保证自动修复；报告接收成功也不保证已经评审、修复或发布。未验收版本不会自动成为客户端更新。

## 发布前保护数据

修复任务只写被授权的客户端工作分支，业务项目和备份目录保持权限边界。更新包先校验再切换元数据；必要配置、项目和持久会话应有独立备份与已验证的恢复点。详见[备份与恢复](backup-recovery.md)。

## 必测故障

首次鉴权失败不产生隐藏 POST；丢失确认后原 UUID 只查询不重发；预览过期或范围变化拒绝执行；忙碌 guard 不丢失任务；APK / EXE 校验失败不能安装；真实安装后数据保留；反馈超大、限流、无效 PNG 与重复报告不得泄露私有内容。
