# 三章流程演示：从手机要求到客户端修复

这是一段约 80 秒的教学动画，展示 Lazy Doggy 蓝图的工作方式。所有任务、补丁、事件和状态均为合成示意；不是生产录像，也不是新的原生客户端操作录像。画面常驻显示“流程演示 · 合成数据 · 非生产录像”。

[打开可播放、暂停和拖动的交互演示](../demos/index.html) · [下载 MP4](../assets/demo/lazy-doggy-demo.mp4) · [中文字幕](../assets/demo/lazy-doggy-demo.zh.vtt)

演示只运行浏览器内的动画，不发送模型或业务请求，不执行命令。页面会加载本站的静态脚本、样式、原生截图缩略图和视频。缩略图来自[已审阅的真实客户端合成演示界面](screenshots.md)，原图没有修改；反馈草稿当时已取消。动画中的 Android 更新卡片是流程示意。

## 第一章 · 手机 → 服务器 → 电脑

**00:00–00:28。** 手机不是模型执行主机。它将要求送给有权限的服务器窗口，再读取回执和事件。例子是修复本客户端的 Agent 筛选标签，先产生候选补丁。

| 时间 | 画面步骤 | 要理解的边界 |
| --- | --- | --- |
| 00:00 | 手机输入要求 | 保存原请求编号；演示不发送真实要求。 |
| 00:04 | 鉴权成功，保存一次回执 | `accepted` 表示可靠接收，不表示 Agent 已执行。 |
| 00:08 | Tmux broker 检查已有窗口 | 根据原生状态交付或有界排队；按一次 Enter 不证明模型接收。 |
| 00:12 | Agent 组织模型推理与工具 | effort、上下文及文件引用按实际能力传递；工具受授权目录约束。 |
| 00:16 | 按序记录事件，再推回手机 | 累计 Token 与上下文占用分别显示；未知读数不能当作零。 |
| 00:20 | 手机断线，只补读原操作 | 服务器正常且请求已可靠接收时才能继续；不确定的写操作不能自动重发。 |
| 00:24 | Windows 接回同一个窗口 | 读取同一服务端窗口；各端未发送草稿仍属于本地。 |

手机仍须能连到服务器，服务器也须能访问上游模型。服务器出口可能让链路更方便，但不能让完全离线的手机发送消息。断线恢复应读取原请求和缺失事件，不能新建一个任务来猜测原任务是否执行。权限或来源改变时，恢复读取的范围也须重新核对。

服务器集中保存窗口、回执、结果和风险数据，因此应有独立备份与恢复方案。手机本地草稿和登录状态不能替代服务器备份。详见[接口与状态边界](contracts.md)。

## 第二章 · 三个 subagent 分工与合并

**00:28–00:52。** A 负责界面，B 负责回执契约，C 负责回归和说明。每人先得到文件所有权，再在独立 worktree 和分支中修改。

| 时间 | 画面步骤 | 要理解的边界 |
| --- | --- | --- |
| 00:28 | 先约定任务和文件所有权 | 明确各自可修改的范围和共同契约。 |
| 00:32 | 三个 worktree，各有独立分支 | 分支隔离修改；不是容器或执行权限隔离。 |
| 00:36 | 产出候选补丁与验证证据 | 教学中的提交和测试状态不是真实测试成绩。 |
| 00:40 | 主协调者按顺序合并 | 检查基线、语义重叠和冲突；保留各提交记录。 |
| 00:44 | 对合并后的结果跑共同回归 | 单分支通过不能代替组合测试与原生验收。 |
| 00:48 | 形成可审阅的候选版本 | 交付补丁、证据和限制；尚未获得生产发布权限。 |

执行权限仍由容器／VM、账号和授权目录承担。三个工作区不能因为共享一个 Git 基线就互相修改运行数据。主协调者负责合并后共同验证，必要时处理同一接口上的重叠改动。详见 [AI 搭建与协作说明](ai-build-playbook.md)。

## 第三章 · 修复本客户端 → 验收 → 手机升级

**00:52–01:20。** 例子是本客户端自身的窄屏标签 Bug 或新功能，不是让服务器自动修复任意业务项目。

| 时间 | 画面步骤 | 要理解的边界 |
| --- | --- | --- |
| 00:52 | 先保存客户端自身的问题材料 | 反馈接收和私有保存已验收；本动画没有提交报告。 |
| 00:56 | 确认问题、候选方向和影响范围 | 目标是完整名称、横向拖动与计数保留。 |
| 01:00 | 取得修复授权，再进入独立分支 | 报告是不可信输入，不能自行扩大执行权限。 |
| 01:04 | 候选补丁要通过真实回归 | 小屏幕、放大字体、附件和恢复逻辑须实际测试。 |
| 01:08 | 授权构建发布，验收候选安装包 | 修复、构建和发布分别确认范围；核对包身份与数据保留。 |
| 01:12 | 手机取得已验收的正式版本 | 下载正式 APK，核对大小、摘要和签名连续性。 |
| 01:16 | 系统确认安装，服务端任务保留 | 用户经 Android 系统确认；电脑有独立更新入口。 |

**反馈保存和应用更新已验收；一键全自动修复 worker 未验收。** 自动修复状态回传、自动生成安装包和自动发布属于重建目标，需要单独实现、授权和验收。保存报告不能证明修复已经完成，也不能给报告内容授予执行权限。

手机可完成反馈、查看候选结果、获取已验收安装包及系统安装确认；服务器负责被授权的修复、测试和构建。本片不会提交反馈、启动 worker、下载真实安装包、发布版本或安装软件。详见[更新与客户端反馈](updates-feedback.md)。
