# 新原创白板：先检查、修理，再考虑搭建

**这个示例不能直接复用部署。请先让自己的 AI 检查代码、修理缺陷，并按完整蓝图补齐安全和验收。**

我们没有定位到可确认为旧版的脱敏白板，因此按公开契约重新写了[最简本地示例](../examples/whiteboard/README.md)。它不是原完整程序，不是已验收客户端，也不能连接真实服务。

## 能看什么

| 演示 | 实际行为 |
|---|---|
| 四个 Agent 按钮 | 四个假标签，共用固定演示回答 |
| effort 与上下文 | 校验并回显选项，不改变真实模型 |
| 发送 | 只接收固定结构；用户不能输入真实任务正文 |
| 模拟确认丢失 | 故意忽略 POST 响应，再 GET 原 UUID，无自动重放 |
| 事件 | 同一次 handler 即时生成 accepted/running/done，不是异步 runner |
| Tokens | 每次固定输入12、输出8；累计与合成上下文占用分开 |
| 缓存盘点 | 固定不完整且未知；无上传、释放、删除或磁盘清理入口 |

仅 Python 标准库和本地 HTML/CSS/JS，无安装依赖。代码不读取原项目、凭据或用户文件，不调用模型，不启动 CLI，不执行 shell，不建立持久守护进程。服务器只读自己的固定前端文件，内存记录最多64条。

手机/Windows浏览器可以阅读静态页面。只有同一设备的本机 HTTP 服务提供互动；没有跨设备远程访问设计。示例没有图片、外部脚本、字体、遥测或第三方资源请求。

## 这些风险和 TODO 还没解决

1. **没有身份认证。** Host/Origin 和固定演示头只防部分误调用，不是登录或用户隔离。不能对外监听、代理暴露或做真实控制。
2. **没有持久性。** UUID仅保存在页面变量，回执只在进程内存；刷新、崩溃、重启都可能失去恢复证据。不能据此声称真实请求可安全重试。
3. **没有真正并发与队列。** 标准库单线程 mock会串行处理；事件没有journal代次、WS补读、多worker锁或原生执行证据。
4. **参数和统计是假的。** 四个 provider 并未证明支持同一effort/context；Tokens不是账单、额度、服务器真实用量或容量实测。Kimi未实现。
5. **没有附件生命周期。** 不提供文件picker、lease、outbox、回执验证、共享副本和安全回收；禁止直接添加一个按年龄删除文件的接口。
6. **没有生产维护。** TLS、撤销、限流、日志策略、审批、取消、隔离、反馈、更新、签名、回滚、drain均未实现。
7. **页面仅有基础可用性。** 未做原三个客户端的Android/Windows原生验收；浏览器、辅助技术和错误恢复仍需自己的测试。

`/demo/`只是教学接口，不是[公开 v1 契约](contracts.md)的实现，不能拿既有客户端直连。没有“装好就能用”的承诺。

## 交给自己的 AI 的最小任务

> 先只读审查这个白板，列出实际缺陷和仍缺失的安全/状态能力。不要连接模型、读凭据、执行真实命令或删除文件。先用临时fixture补持久UUID/outbox、事务去重、事件journal和认证/撤销测试；再依据contracts与acceptance写分阶段计划。真实模型调用、主机部署、停止窗口及发布分别等待明确授权。保留失败证据，不把mock测试当作生产验收。

按[后端构建顺序](backend-build.md)、[适配器设计](agent-adapters.md)和[验收门禁](acceptance.md)逐步替换 mock。原程序踩过的问题见[已知问题](known-bugs.md)，这里没有自动继承那些修复。
